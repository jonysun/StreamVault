# 抖音请求证据分级与风险处理实施计划

1. 扩展 Python F2 错误对象，携带分类依据与证据置信度。
2. 将 HTTP 401/403、429、结构化登录/验证码字段与模糊文本分离；后者输出 `F2_AUTH_OR_VERIFY_SUSPECTED`。
3. 将作者资料、作者作品列表和详情请求的安全请求身份、尝试记录和最终请求证据纳入结构化错误。
4. 在 Java 增量抓取服务中保留受限长度的结构化诊断，并在任务失败/冷却时输出统一的安全证据摘要。
5. 仅让确认的 401/403、429 和结构化验证字段调用全局风险冷却；疑似验证使用作者任务短退避。
6. 为 Python 与 Java 增加分类、冷却边界、脱敏和日志摘要测试。
7. 执行 Python 测试、相关 Java 测试、完整 Java 测试、编译和差异检查。
