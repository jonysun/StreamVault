# 缩略图补齐：优先恢复平台封面

用户已确认顺序：复用本地封面 → 尝试保存的封面 URL → 刷新详情获取新 URL → 最后抽帧。沿用 `streamvault-backfill-thumbnails` 命令与已有参数。

直接在 Python 中重写 F2/DTK 会绕开现有 Cookie、风控和节点控制；仅从旧 JSON 找 URL 又无法恢复过期或脱敏签名。因此 Python 负责本地文件、旧封面提取和补齐写回，通过仅允许回环地址且校验应用 token 的接口调用现有 Java 平台适配器，仅获取新封面，不修改作品元数据或下载视频。刷新需校验作品与平台身份。

预览不发送网络请求、不运行 ffmpeg、不写数据库，分别报告 would_reuse / would_download / would_refresh / would_generate。这些是首选步骤，不代表旧 URL 一定可用。正式执行逐条串行，刷新有间隔、网络与子进程有超时；每条完成即提交，便于中断后续跑。只在封面成功落盘后写回 videocover。

验证：覆盖本地封面预览、嵌套原始 JSON、过期 URL 后刷新成功不抽帧、刷新失败才抽帧、身份冲突拒绝、认证拒绝与无副作用、SQLite 真实命令流程及再次运行幂等。更新运行说明。不会连接生产数据库或全量运行补齐。
