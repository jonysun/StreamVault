# 抖音作者账号不可用自动停用设计

## 目标

当抖音上游明确返回作者已注销、账号不存在或明确封禁时，自动停止该作者对应的收藏任务，展示结构化的“已删号/已封禁”状态，并保留作者档案、收藏历史、作品数据库记录和本地媒体文件。用户手动恢复任务后，清除停用状态并重新注册 Quartz 调度。

## 边界

Cookie 失效、验证码、429、网络错误、上游 schema 错误、未知 `special_state_info` 和普通 `user_not_see` 不得触发永久停用。已有下载项与停用无关，继续使用下载执行时租赁的 Cookie 处理。

## 状态与事务

在 `biz_collect_data` 增加远端账号状态、原因和检测时间字段。抓取得到强证据后，在收藏运行入库事务中同时写入停用字段、`taskenabled=N` 和任务展示状态；当前运行仍正常完成并记录停止原因。事务提交后移除 Quartz 调度，避免数据库事务与调度器产生跨资源不一致。

手动恢复沿用现有“开始任务”入口：清除远端停用字段，设置 `taskenabled=Y`，保存后重新注册调度。恢复不删除历史运行、作品或媒体。远端停用期间，运行明细不参与常规历史清理，避免作者作品列表因保留期策略消失。

## 远端分类

Python 层保留 `ACCOUNT_DEACTIVATED` 与新增的 `ACCOUNT_BANNED` 成功结果，仅由明确的注销/不存在/封禁证据产生。Java 层将两者映射为停用状态和不同中文标签；其余不可用结果只记录为本次抓取提示，不改变任务启用状态。

## UI 与验证

任务列表显示停用标签、远端原因和检测时间；停用任务仍可查看历史列表和下载队列。测试覆盖严格状态识别、空抓取不覆盖回填状态、自动停用、Quartz 移除、手动恢复、下载队列继续、SQLite/PostgreSQL 字段初始化及既有功能回归。
