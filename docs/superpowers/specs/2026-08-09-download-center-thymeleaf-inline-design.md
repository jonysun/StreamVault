# 下载中心 Thymeleaf 内联解析修复设计

## 问题

生产环境访问 `/admin/downloadCenter` 时，Thymeleaf 在解析
`templates/admin/downloadCenter.html` 第 247 行失败。该行的 JavaScript 二维数组以
`[[` 开头，而 Thymeleaf 将 `[[...]]` 识别为内联输出表达式，因此把数组内容错误地交给
Spring EL 解析。日志中的中文乱码是异常输出的字符集表现，不是模板源码损坏。

## 目标与边界

- 下载中心页面能够被 Thymeleaf 正常解析和渲染。
- 状态筛选的值、顺序和中文文案保持不变。
- 不修改下载队列、数据库或 API 行为。
- 用自动化测试复现并防止同类模板解析回归。

## 方案比较

1. 在两个相邻数组左括号之间加入空白，例如 `[ ['ALL', ...]`。JavaScript 语义不变，
   同时不再形成 Thymeleaf 的 `[[` 标记。改动最小，采用此方案。
2. 把状态选项提取为顶层常量或改用 `Array.of(...)`。同样可行，但会扩大本次修复范围。
3. 对整个脚本启用 `th:inline="none"`。可能影响页面未来合法使用 Thymeleaf 内联变量，
   且隐藏同类问题，不采用。

## 实现

- 将下载中心活动状态和历史状态两个二维数组从 `[[...]]` 改为 `[ [...] ]` 形式。
- 检查后台模板中其他非 Thymeleaf 用途的连续 `[[`；仅修复确认属于 JavaScript 数组且
  会进入模板解析器的同类位置。
- 在模板测试中使用 Thymeleaf 引擎实际处理下载中心模板，而不只做字符串包含断言。

## 验证

- 回归测试在修复前因 `TemplateInputException` 失败，修复后成功。
- 运行后台模块针对性测试和完整 Maven 测试。
- 执行 `git diff --check`，确保没有编码或空白问题。

## 风险

修复不触及业务数据。主要剩余风险是其他旧模板存在相同的裸 `[[` 数组语法；扫描结果将
区分合法的 Thymeleaf 内联表达式和普通 JavaScript 数组，只处理后者。
