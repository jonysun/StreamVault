# 下载中心图标与批量选择保持设计

## 问题

- 侧边栏使用 `mdi-download-circle-outline`，但项目当前打包的 Material Design Icons
  样式表不包含该图标，因此下载中心入口只显示文字。
- 下载中心每 3 秒自动刷新任务列表。`renderRows()` 会重建所有行并清空复选框，用户无法在
  自动刷新间隔内稳定完成多选和批量操作。

## 目标与边界

- 侧边栏下载中心入口显示当前图标库支持的下载图标。
- 自动刷新时，仍在当前结果页中的已选任务保持勾选。
- 切换标签、筛选条件、关键词或分页时清空选择，避免对不可见任务执行批量操作。
- 当前结果页中的任务消失或变为不可选择时，从选择集合中移除。
- 全选、取消全选和批量操作继续使用现有后端接口。
- 不跨浏览器刷新持久化选择，不修改数据库和下载队列行为。

## 方案比较

1. 在页面状态中维护当前页任务键集合。自动刷新重绘时按任务键恢复勾选，并与最新结果取
   交集。实现直接、不会积累隐藏任务，采用此方案。
2. 选中任务后暂停自动刷新。可以保留 DOM 状态，但页面会停止展示实时下载进度，不采用。
3. 使用 `sessionStorage` 跨页面持久化。可能保留过期或已变更状态的任务，超出本次需求，
   不采用。

## 实现

- 将侧边栏类名改为当前样式表存在的 `mdi-download`。
- 在下载中心 `state` 中增加 `selectedKeys` 集合。
- 复选框变更时同步集合；全选只作用于当前页可选择任务。
- 行重绘前根据最新当前页可选择任务裁剪集合，生成行时恢复 `checked` 状态。
- 显式切换标签、筛选、搜索或分页前清空集合；自动刷新不清空。
- 批量重试或隐藏成功后清空集合并刷新。

## 验证

- 模板测试验证侧边栏使用存在的图标类。
- JavaScript 结构测试验证选择集合、重绘恢复、显式清空和批量操作清空均已接入。
- 真实 Thymeleaf 渲染测试继续通过。
- 运行完整 Maven 测试及 `git diff --check`。

## 风险

选择只在当前页面内存中保存。浏览器整页刷新、切换筛选或翻页后选择会清空，这是为避免
批量操作不可见或过期任务而设定的明确行为。
