# 下载中心错误类型筛选与批量处理

## 意图

让下载中心按结构化错误码筛选失败记录，并复用现有的跨页选择和批量动作，方便分别处理目标已存在、DTK 冷却、作品不存在等错误。

## 目标

- 错误类型作为独立筛选条件，不依赖关键词搜索。
- 当前筛选结果可以跨页全选，再使用现有批量按钮。
- DTK 冷却记录可批量重新排队。
- `DOWNLOAD_TARGET_EXISTS` 可批量重新排队，后续尝试使用已有替换流程。
- `DTK_WORK_NOT_FOUND`、`F2_WORK_UNAVAILABLE` 可批量标记远端已删除或清除历史记录。
- 保留现有单条重试、清除记录、标记远端删除行为。

## 非目标

- 不新增独立错误管理页面。
- 不自动删除错误记录。
- 不改变错误分类和队列最大重试次数。

## 方案

扩展下载中心现有 `items` 和 `transition` API，增加 `errorCode` 参数。收藏队列和直链队列分别在自己的 SQL 分支中按错误码过滤，再合并分页结果。页面增加错误类型下拉框，筛选变化时清空当前选择并重新查询。批量动作继续调用现有 `transition` 接口，因此“全选当前筛选结果”与已有权限、状态校验保持一致。

错误类型下拉框提供目标已存在、DTK / 抖音冷却、远端不可用三类。后端同时读取结构化错误码和旧记录错误文本，因此部署前产生的错误也可归类；具体错误详情仍可通过原有详情按钮查看。其它错误保留在“全部错误类型”中，可用详情和关键词检查。

## 操作语义

- 冷却类：筛选后点击“重试所选任务”，调用现有 `RETRY`。
- 目标已存在：筛选后点击“重试所选任务”，复用现有有限重试和第二次替换逻辑。
- 远端不可用：切换到历史记录，将来源设为“收藏下载”并筛选，再使用现有“标记远端已删除”；收藏队列中的 DTK / F2 不可用项会保留并进入已删除状态。也可用现有“清除所选记录”按筛选跨页隐藏历史。该动作不会删除媒体文件。

## 验证

- 查询 API 只返回匹配 `error_code` 的记录，跨收藏和直链来源均成立。
- 全选当前筛选结果时，批量转换只作用于该错误码，不影响其他错误。
- 现有下载中心测试继续通过，并增加错误码筛选和批量动作覆盖。
