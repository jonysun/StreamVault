# 图文视频自动播放与抖音作者自动归集设计

## 目标

图文作品在媒体播放页和图文列表的大预览中，当前页为视频时自动播放；缩略图不自动播放。

所有新入库的抖音作品以 `sec_uid`（`MS4...`）作为唯一作者键。只要上游作品、hybrid 数据或收藏任务地址中任一处提供该值，作品行和作者档案都必须自动归集，不能依赖事后手工修复。

## 播放行为

`/admin/index` 的活动图文幻灯片在视频元素已可播放后调用播放。切换幻灯片、切换作品和销毁播放项时暂停并重置旧视频，避免后台继续播放。

`/admin/graphicContentList` 的大预览仅播放当前媒体项。打开图文集或切换到视频页时触发播放；网格缩略图保持暂停。

播放先沿用当前全局静音状态。若浏览器因自动播放策略拒绝有声播放，则将该活动视频静音后立即重试，并同步该播放页的静音状态。视频结束后沿用各页面既有的翻页或循环策略。

## 抖音作者身份

`sec_uid` 是抖音的 canonical author ID；数字 `uid`、`unique_id` 和昵称均不是归集键。保存作品前按以下顺序解析 canonical ID：

1. 作品列表响应中的 `author.sec_uid` 或顶层 `sec_uid`。
2. hybrid 详情响应中的 `data.author.sec_uid`。
3. 收藏任务地址 `postMS4...` 中携带的 `MS4...`。
4. 作者 profile 响应中的 `sec_uid`。

一旦解析到合法 `MS4...`，视频或图文行的 `authoruid` 与 `secuid` 都写入该相同值；作者档案以 `platformkey=douyin + authoruid` upsert。昵称、用户名、头像和签名按数据完整度补全，但不能覆盖更完整的既有资料为空值。

每条作品入库时都执行一次本地作者档案 upsert，以保证作品与 canonical author ID 立即关联；这不是外网请求。外部 profile API 按作者和单次任务运行缓存，同一作者每轮最多请求一次。作品响应已经包含完整作者资料时不请求 profile；仅缺少用户名、签名等可补充字段时才请求。profile 请求失败不阻断作品入库，只要已有合法 `MS4...`，仍创建或更新基础作者档案，后续任务可继续补全。

解析不到 canonical ID 的非抖音作品可保持无作者档案。抖音作品则记录明确诊断日志，包含作品 ID、任务 ID 和每个候选源是否存在，便于发现上游字段变化。

## 手动刷新作者档案

作者列表每行增加“刷新”按钮。按钮仅对具有合法 canonical `MS4...` 的抖音作者启用，并通过管理员鉴权的 POST 接口发起一次外部 profile 请求。请求期间按钮进入加载和禁用状态，防止重复提交。

外部响应通过 canonical UID 和字段格式校验后，在一个数据库事务内完成以下操作：

1. 仅使用非空返回字段更新 `biz_author_profile` 的当前昵称、用户名、头像、签名和主页。
2. 昵称发生变化时记录作者历史名称。
3. 按相同 canonical UID 批量更新 `biz_video` 和 `biz_graphic_content` 的作者昵称、用户名、头像、主页以及 `authoruid/secuid` 双 UID 字段。
4. 不修改作品标题、描述、发布时间、媒体路径和原始 JSON。

作品同步使用定向批量更新，不加载作品实体及其大 `jsonData` 字段。外部请求失败、响应缺少合法 `MS4...` 或返回作者 UID 与目标作者不一致时不写库。接口返回作者字段更新数、视频更新数、图文更新数和可读错误信息；前端成功后刷新当前作者行，失败时保留原数据显示具体原因。

## 边界与性能

不在 `/api/findVideos` 或媒体 Feed 的读取路径解析 `jsonData` 或修复数据库。读取 API 保持轻量，避免 1.9GB 数据库上出现大 JSON 反序列化和隐式写入。

本次不修改历史生产数据。既有“作者列表修复”入口继续用于历史缺失记录；新作品在入库时完成归集。不会改变 `ConfigEntity.java` 的现有本地修改。

## 验证

增加或更新测试覆盖：

- 图文预览的活动视频触发播放，离开后暂停；自动播放被拒绝时静音重试。
- 收藏列表项只有数字 `uid`，但 hybrid 或任务地址有 `MS4...` 时，保存的视频写入双 UID 字段并创建作者档案。
- 同一任务的一批作品属于同一作者时，外部 profile API 最多调用一次；已有完整作者资料时不调用。
- profile 请求失败但已有 `MS4...` 时，作品和基础作者档案仍正常保存。
- 缺失 canonical ID 的抖音作品不错误地使用数字 `uid` 创建作者档案，并输出可定位诊断。
- 手动刷新使用目标 `MS4...` 请求一次 profile，并把非空资料批量同步到作者档案、历史昵称及该 UID 的视频和图文。
- 手动刷新遇到外部失败、UID 不一致或非法响应时不产生部分数据库更新。
- 手动刷新批量更新路径不读取或重写作品 `jsonData`。
- 轻量视频/图文 Feed 继续直接返回已存的 canonical UID，不读取大 JSON。
