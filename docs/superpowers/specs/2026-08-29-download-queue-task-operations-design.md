# 下载队列与收藏任务操作设计

## 目标

解决抖音媒体 CDN 地址过期、收藏下载项永久等待作者列表快照、删除收藏任务后残留队列、当前任务无法批量处置、后台 API 登录状态误报，以及无法手动解除抖音全局冷却的问题。

## 设计原则

- 原始作品网页链接与 CDN 媒体地址分开诊断；网页可访问不等于旧媒体地址有效。
- 队列状态必须可人工转换、可追踪、可恢复，不能留下无生产者的永久等待项。
- 删除操作只影响当前收藏任务拥有或独占的数据；被其他任务引用的作品和媒体必须保留。
- 继续使用 PostgreSQL 持久队列和现有 `biz_blocked_work` 黑名单，不增加第二套队列或黑名单。
- API 未登录返回 JSON 401，页面请求才重定向到登录页。

## 作品媒体 404

收藏下载使用列表快照中的媒体 URL。媒体请求首次返回 HTTP 404 时，适配器使用作品原始 URL/作品 ID重新获取详情，替换过期媒体资源并只重试一次。新地址仍返回 404 才标记 `F2_WORK_UNAVAILABLE`，展示“可能服务器端已删除或媒体地址已失效”。404 不触发抖音 Cookie 风控冷却。

下载诊断保留原始链接、媒体 URL 安全摘要、刷新前后 HTTP 状态、重试次数和最终分类；不记录签名查询参数或 Cookie 原文。

## 当前任务状态操作

下载中心当前任务允许选择 `QUEUED`、`RETRY_WAIT`、`FAILED` 和可恢复的 `RUNNING` 项。支持：

- 立即重试：普通失败重新排队；快照缺失项先触发作者列表刷新。
- 移入等待重试：保留错误信息并设置下一次可运行时间。
- 标记失败：终止当前等待并进入失败列表。
- 取消队列：取消未完成项并隐藏，不删除媒体文件。
- 删除并拉黑：收藏项写入现有作品黑名单并取消相同作品的未完成项。

`LIST_SNAPSHOT_PENDING` 必须显示为“等待作者列表刷新”，同时显示所属收藏任务、作品 ID、最近刷新时间、下一次重试时间和阻塞原因。

## 收藏任务删除

删除收藏任务提供三种策略：

1. 删除所有：停止调度，取消未完成队列，删除当前任务独占的作品记录和本地媒体。若作品仍被其他收藏任务或业务记录引用，则保留作品和文件。
2. 删除任务，保留队列和已下载：停止调度并软删除任务展示记录，保留所有队列和已下载数据；队列完成后不自动删除作品。
3. 删除任务和队列，保留已下载：停止调度，取消该任务的 `QUEUED`、`RETRY_WAIT`、`FAILED` 及可恢复 `RUNNING` 项，保留作者、作品记录和媒体。

默认推荐第三种。每次操作返回取消队列数、保留数、删除数和因共享引用而保留数。运行中的下载不强杀，先标记取消意图，由租约结束后的状态转换完成清理。

## 登录与会话

登录拦截器对 `/admin/api/**` 返回 HTTP 401 和 `AjaxEntity` 登录错误 JSON；普通 `/admin/**` 页面继续重定向。下载中心统一处理 401，提示会话失效并跳转登录页。登录成功、session 创建/失效和 API 拒绝记录请求路径与 session 是否存在，不记录 session ID 或 Cookie 值。

## 手动解除抖音全局冷却

系统配置的抖音 Cookie 区域增加“解除全局风控”按钮。接口清除当前实例的强风控和详情软冷却时间戳，不修改 Cookie、不立即发起远端请求，并记录操作人和时间。解除后下一次请求仍按正常证据重新判断，不能永久绕过风控。

## 数据与测试

- 不新增删除专用黑名单，复用 `biz_blocked_work`。
- 队列状态转换使用数据库事务和租约条件，避免误更新其他 worker 的任务。
- 测试覆盖媒体 404 刷新成功/失败、快照等待项人工转换、三种任务删除策略、共享作品保护、API 401 JSON、冷却清除及权限校验。
